# 源插件编写范式

> 一源一包的标准结构与全部硬约束。从 14 个已上线源包（fq/sq/qm + asyn-panel 批 10 个 + qq_luomu）的实践中提炼，
> 与 `AGENTS.md` §1.5 同源；写新源前通读一遍，改源时对照检查。
> 权威代码样例：`plugins/qm_novel/0.1.0`（最全：会话池/加密/发现）/ `plugins/qq_luomu/0.1.0`（最简：纯 JSON API）。

## 1. 目录结构（源码即插件）

```
plugins/<code>/                       # 部署单元：整棵拷走即可在别的机器加载
├── deps/                             # 该 code 的多版本共享依赖，由 pnpm run sync:plugins 维护
│   ├── contract/                     # SDK 源码副本（TS 不能放 node_modules：strip-types 会拒绝）
│   └── source-kit/
├── node_modules/                     # 第三方纯 JS 包（zod/cheerio 及其闭包），真实文件、无软链
└── <version>/                        # 源码即插件；版本目录是 host 换代/回滚的单位
    ├── manifest.json                 # 唯一声明位：code/actions/params/required_params/media_type
    ├── index.mjs                     # 薄入口：export { default } from './src/index.ts'
    ├── protocol/                     # 可选：非 TS 资产（如 fq_novel 的 ESM 协议树），随插件走
    ├── src/
    │   ├── index.ts                  # defineSource({ handlers })：只有"取数 + 调映射"
    │   ├── protocol.ts               # 签名/加密/会话/端点 URL 与参数装配
    │   ├── normalize.ts              # 上游结构 → contract DTO 的**纯函数**
    │   ├── explore.ts                # 可选：发现页（栏目字典 + URL 装配）
    │   ├── endpoints.ts              # 可选：端点常量 + 参数装配
    │   └── pool.ts                   # 可选：会话/设备池
    └── test/
        ├── normalize.test.ts         # 必有：映射纯函数夹具用例（不连网）
        └── protocol.test.ts          # 有签名/加密时必有：黄金向量钉住算法（不连网）
```

**两条依赖硬规则**（`tools/check-layers.mjs` 强制）：
① 版本目录里 **不许裸 `@loomproxy/*` import**——`@loomproxy/contract` / `@loomproxy/source-kit`
写成到 `../../deps/...` 的相对路径（独立目录没有 workspace 解析链）；插件只许依赖这两个 SDK，
不许 import store/gate/api/host，也不许插件之间互相 import。
② **plugins/ 下不许有任何软链**（`plugins/node_modules -> ../node_modules` 这种尤其禁止）：
拷走就断、换机器就断。第三方 JS 包以真实文件放 `<code>/node_modules/`，多版本共享。

## 2. manifest.json 字段表

```jsonc
{
  "sdk_version": "^1",              // 与宿主 SDK 主版本兼容（host 会校验）
  "isolation": "in-process",        // 或 "worker"（独立线程，取数回主线程桥）
  "entry": "./index.mjs",           // 版本目录里的薄入口，指回 src/index.ts（无打包步骤）
  "params": {                       // 每个动作接受哪些 query 键（只注入声明过的键）
    "search":  ["query", "key", "page"],
    "detail":  ["bookId"],
    "chapter": ["bookId"],
    "content": ["bookId", "itemId"],
    "explore": ["category", "page"]
  },
  "meta": {
    "code": "<与目录名逐字一致>",    // 不一致宿主直接拒载
    "display": "显示名",
    "category": "分类短码",          // 如 fq/sq/qm/qq/hg
    "description": "一句话说清协议形态",
    "sort_order": 20,
    "status": 1,
    "actions": ["search", "detail", "chapter", "content", "explore"],
    "required_params": {            // 缺参由底座挡成 400（不进 handler，不产生假正文）
      "search": ["query"], "detail": ["bookId"], "chapter": ["bookId"],
      "content": ["bookId", "itemId"]
    },
    "fixed_base_url": true,         // URL 模板由包下发、不收 baseUrl 参数（绝大多数源都是）
    "media_type": "novel",          // 单媒介源必须声明；多媒介源用 search_tabs 区分
    "search_tabs": [                // 与 meta.media_type 二选一互补
      { "tab_type": 3, "bd_id": "2", "name": "小说", "media_type": "novel" }
    ]
  }
}
```

命名约定：`<站点>_<媒介>`（如 `sq_audio`/`sq_comic`）。**平台不做源特例**——形态由包自己的
`meta.media_type`/`search_tabs` 与字段映射决定。

## 3. 硬约束（违反 = 违反 AGENTS.md，review 直接打回）

| # | 约束 | 理由 |
|---|---|---|
| 1 | **上游请求只走 `ctx.fetch`**（`json`/`text`/`raw`），不自建 undici/fetch/curl | 绕开它就绕开了熔断/代理池/共享缓存/合并 |
| 2 | **Node strip-only 语法**：不用 `enum`/`namespace`/构造器参数属性/装饰器；类型导入一律 `import type` | Node 24 直接跑 .ts，tsc 只做类型检查 |
| 3 | **映射逻辑进 `normalize.ts` 且为纯函数**，handler 里不许拼 DTO | 换源时 normalize 是唯一要改的地方，必须可单测 |
| 4 | **错误一律带内**（`inBandError(msg, {reason})`），文案过 `scrubQuery`，含 `://` 的原文一律换固定句 | 正文环节 5xx 会让下游换源重试，放大抖动；URL/签名串不外泄 |
| 5 | **DTO 字段名逐字照 `contract/src/legado.ts`**；`kind` 首项留空（平台出口统一打标源码）；缺失字段是 `''`/0，不是 null | 契约漂移 = 破坏下游 |
| 6 | **算法/常量逐字节对齐参考实现**，黄金值用例钉住（`test/protocol.test.ts`） | 签名差一位 = 整批 403，且难查 |
| 7 | **凭据/密钥常量只进代码不进文档**；错误消息不含 target/签名/密文 | 泄露面控制 |
| 8 | **不许 vm 跑外部 jsLib、不许同步 HTTP**（参考实现里的 `java.*` 桥要换成 Node crypto + ctx.fetch） | Legado 桥是 Rhino 绑定，服务器没有 |
| 9 | `test/` 不连网、不连 MySQL/Redis | CI 门禁要求 |

## 4. 三种转写形态（按参考实现选路）

| 形态 | 参考在哪 | 做法 | 样例 |
|---|---|---|---|
| **复用** | 维护者的独立 ESM 协议树 | 动态 import 其 `getSite()`；协议树随插件放在 `<version>/protocol/`（相对路径解析，`FQ_PROTOCOL_DIR` 可覆盖）；本包只写 DTO 适配 | `fq_novel` |
| **转写** | Legado jsLib / Node adapter / Go 源码 | 算法逐字节转写进 `protocol.ts`（Node crypto 替 java.*/Rhino），黄金值钉住；**宿主桥全部换掉** | `sq_novel`/`qm_novel`/`tadu`/`lianshang` |
| **直译** | 纯 JSON API 的 Node adapter | `ctx.get→{ok,body}` 换成 `ctx.fetch.text`+JSON.parse，映射照抄 | `qq_luomu`/`huaben` 等 |

选型原则：**能转写不复用**（少一个外部路径依赖）；签名体系相同的多源**复用第一份实现**
（`hg_drama` 复用 `fq_novel` 随包 sign 模块，不抄第二份防漂移）。

## 5. protocol.ts 写法要点

- **常量区块化**：主机/密钥/字母表集中导出并注明出处（`jslib/xxx` 或 `sources/xxx.go:行`），上游一变有处可查。
- **签名函数纯函数化**：输入明文输出签名，注入时钟/随机源才可测（参考 `qm_novel` 的 `RandomHex`）。
- **会话状态用内存单例 + 可注入**：token/设备指纹缓存进程内即可；`pool.ts` 导出 `getSessionPool()`，
  Device/时钟/登录函数留注入口供单测（参考 `qm_novel/src/pool.ts`）。跨重启的凭证池走平台号池
  （`def.pool` 声明 → `compose` 注册 `packages/pool`），**不要**自己写文件锁。
- **OpenSSL 3 陷阱**：`des-ecb` 在默认 provider 不可用（`ERR_OSSL_EVP_UNSUPPORTED`），服务启动参数不由插件控制
  → 用纯 JS DES（`yueyou_novel`）或 `des-ede3-ecb` 三同钥等价实现（`tadu_novel`）。
- **正文可能是数组/密文/分页**：数组 join('\n')、密文先解密、分页并行跟完再拼（`deqi_novel` 正文分页）。
- **限频状态最省事的做法**：上游要 token 就做模块级缓存 + 临期重取（`qq_luomu` 无此需求；`qm_novel` 用池）。

## 6. normalize.ts 写法要点

- 每个动作一个 `toXxx(raw): ContractDTO` 导出；内部只做**字段挑选/拼接/格式化**，不发请求。
- 空语义：上游没有的字段给 `''`/0；`omitempty` 语义用 `undefined`（contract 的 optional）。
- 时间戳统一一个 `formatTime`（秒/毫秒自适应）；字数统一 `formatWordCount`（"0" 兜底）。
- 章节 `itemId` 要**自包含**：正文环节只拿 bookId+itemId 两个参数，所以 itemId 必须带齐定位信息
  （如 `bid|cid`、AES 密文 path、完整章节 URL——参考 `maoyan`/`midu`）。避免 `data:xx;base64,…` 这类
  带 `,`/`{`/`"`/`=` 的载体，会污染 URL（`yueyou_novel` 的教训）。
- 搜索结果先过缓存写入（在 index.ts 的 observe 里自动发生，normalize 不负责）。

## 7. index.ts 骨架（照抄即可）

```ts
import { inBandError, keywordOf, paramString, scrubQuery } from '../../deps/contract/src/index.ts'
import { defineSource, type HandlerContext } from '../../deps/source-kit/src/index.ts'
import { fetchSearch, fetchDetail, fetchToc, fetchContent } from './protocol.ts'
import { toSearchResponse, toBookDetail, toChapterResponse, toContentResponse } from './normalize.ts'

function inBandFromError(e: unknown) {
  const raw = e instanceof Error ? e.message : String(e)
  const msg = raw.includes('://') ? '上游请求失败，请稍后重试' : scrubQuery(raw)
  return inBandError(msg, { reason: 'upstream_network' })
}

export default defineSource({
  handlers: {
    async search(ctx: HandlerContext) {
      const key = keywordOf(ctx.params).trim()
      if (!key) return inBandError('缺少搜索词', { reason: 'parse_empty' })
      try {
        return toSearchResponse(await fetchSearch(
          (url, opts) => ctx.fetch.text(url, opts), key, pageOf(ctx),
        ))
      } catch (e) { return inBandFromError(e) }
    },
    // detail/chapter/content 同形：缺参带内报错 → fetch → toXxx；content 用 textContent(content)
  },
})
```

## 8. 测试要求（缺一不算完成）

1. **normalize.test.ts（必有）**：上游响应样本夹具 → 断言 DTO 每个关键字段；空数据/异常形状不抛。
2. **protocol.test.ts（有算法时必有）**：黄金向量钉住签名/加密/编码——期望值必须来自**独立实现**
   （Python/openssl/参考实现实跑），不许拿自己的输出钉自己。
3. **真网探针**：`node tools/plugin-run.mjs <code> search query=…` 跑通一个动作（AGENTS.md §4）。
   上游风控/token 失效跑不通时**如实记录**（WORKLOG + 带内错误透出原因），**不许伪造数据让探针变绿**。
4. 全量门禁：`pnpm run check`（分层/tsc/面板/契约/全部用例）。改依赖后跑 `pnpm run sync:plugins`
   重建 SDK 副本与 JS 依赖闭包，别手改 `deps/` 或 `<code>/node_modules/`。

## 9. 上线清单（无打包步骤）

```
pnpm run sync:plugins                    # ① 依赖一致性：改依赖/换机器后重建 deps 与 node_modules
scp -r plugins/<code>/ <server>:$PLUGIN_DIR/   # ② 部署一个 code（含 deps + node_modules + 所有版本目录）
POST /admin/sources/reload-all            # ③ 热加载（或重启服务让它自动扫描）
curl /<code>/search?query=…               # ④ 真网跑通一个动作；/admin/sources/plugins 里 state=active
# ⑤ WORKLOG §2 包表加一行 + 踩坑（如有）记 §6
```

`plugins/<code>/` 整棵自包含：不依赖 `packages/` 树、不依赖仓库根 `node_modules`，也不需要
`pack-plugin.mjs`（已退役）。`POST /admin/sources/install-package` 仍可装 zip，包根或
`<code>/<version>/` 前缀都认。

## 10. 已知坑（踩过的，别再踩）

- **绝不在 plugins/ 下建软链**：`plugins/node_modules -> ../node_modules` 相对路径拷出仓库就断，
  绝对路径换机器就断；Node 的 strip-types 还拒绝加载 `node_modules` 下的 `.ts`，所以 SDK 只能放
  `deps/` 并写相对 import，第三方纯 JS 包才进 `<code>/node_modules/`（真实文件）。
- **fq_novel 的协议树是 39 个非 TS 资产**：同步工具只搬 `src/**.ts` / `test/**.ts`，
  `protocol/` 必须随版本目录一起在；缺了它的症状是启动日志「建号失败: Cannot find module
  …/protocol/api/core/device.mjs」。

- **DES**：OpenSSL 3 默认 provider 没有 DES → 纯 JS DES 或 3DES 三同钥（见 §5）。
- **vm/jsLib**：Legado 的 `java.ajax` 是同步语义，转写时必须换成 async ctx.fetch，控制流要重排。
- **动态域名**：多镜像探测 + 缓存 1h（`acfun_novel`），fallback 域名留死值兜底。
- **UA 门槛**：有的上游按 UA 放行（`qq_luomu` 不带 UA 回"不支持SDK Token"）——协议层固定一个浏览器 UA。
- **章节标识污染 URL**：载体别用 base64 带 `,{}"=`（见 §6）。
- **视频流正文**：CENC/HLS 与 novel DTO 不兼容 → content 如实报
  `inBandError(..., {reason:'unsupported_media', todo:'video_content'})`，**先扩契约再接**，不伪造。
- **媒介判定**：单媒介源 manifest 必须写 `meta.media_type`，否则明细全落"未判定"
  （观测链：响应自带 > tab 声明 > 源默认 > 空）。
- **用户关了阅读留存**：其明细的 media/result_count/标识会被平台抹掉（`withholdContent`，Go 同口径）——
  这是设计内行为，不是插件 bug，不要试图在插件里"补"。
